# 0004 UI 리디자인 (범위·호환·golden·CustomTkinter)
상태: 확정      날짜: 2026-10-27 (사용자 결정 2026-10-13, 단계표 `docs/nav-drafts/ui-stages.md`)

## 조건
- 리팩터링(P1~P5-fix)으로 화면 코드가 `ezbak/gui/` 한 곳에 모였다. 화면을 바꿔도 다른 모듈은 고치지 않는다.
- 요구사항 C4 "하지 않을 것"(프레임워크 교체, UI 리디자인)과 0002 의 고정 축(UI 구성·테마)은 리팩터링 기간의 제한이었다. 이 ADR 이 UI 리디자인에 한해 둘을 푼다.
- Q1 동작 동일 · Q2 자동 테스트만 · C2 PyInstaller onefile · C3 호환 전부 유지는 그대로다.

## 결정
### 1. 범위
- 바꾸는 것: 창 구성(사이드바 + 페이지), 색·간격·글꼴, 대화상자 모양. 단계는 U0~U8(`ui-stages.md`).
- 바꾸지 않는 것: 백업·복원·도구의 동작, 작업 로그, 큐 task 문자열, 번역 키 이름(새 키 추가는 허용), settings.json 키, CLI·예약 작업·산출물 이름(0003 §6 전부).
- 새 데이터 카드(속도 그래프·마지막 백업·다음 예약)는 기능 추가라 U7 에서 따로 커밋·테스트한다. 그 전의 홈은 지금 있는 정보로만 채운다.
- 창 틀은 기본 Windows 제목 표시줄을 유지하고 색만 맞춘다(틀 없는 창은 하지 않는다).

### 2. 툴킷: CustomTkinter
- `customtkinter` 를 배포 의존에 넣는다(버전 고정은 U2). 프레임워크 교체(C4)의 예외로 이것 하나만 허용한다. Qt·웹뷰 등은 여전히 하지 않는다.
- `tkinter` 와 같이 `customtkinter` 도 `ezbak/gui/` 에서만 import 한다(U3 에서 `tests/test_architecture.py` 검사 a 에 추가).
- CustomTkinter 대응 위젯이 없는 것(ttk.Treeview 등)은 ttk 스타일로 토큰에 맞춘다.

### 3. golden 정책
- 동작 golden(작업 로그, 큐 순서, 대화상자 결과, argv, 번역 사전)은 U 단계 내내 그대로 통과해야 한다.
- 창 구조 golden(위젯 트리 스냅샷)은 U4·U5·U6 과 U7(홈 데이터 카드, 2026-10-27 사용자 결정) 의 해당 커밋에서만 Q1 예외로 다시 만들고, 커밋 메시지에 "창 구조 golden 재생성(ADR 0004)"과 바뀐 범위를 적는다.
- 새 화면 문구는 번역 키 추가다. strings_en/ko 를 고치는 발주는 단독으로 돌리고 gui_snapshot translations 도 같이 다시 만든다.

### 4. 브랜치
- main 에서 딴 `claude/continue-work-vipjnn` 를 그대로 쓴다(처음 안 `feature/ui-redesign` 대신, 2026-10-27 사용자 결정). 발주 1건마다 커밋하고 U8 이 끝나면 main 에 병합한 뒤 P6 를 시작한다.

## 근거
- CustomTkinter 는 tkinter 위에 있어 지금의 믹스인·큐·bridge 구조와 테스트 도구를 그대로 쓸 수 있다. 다른 프레임워크는 GUI 전체를 다시 쓰고 테스트 기반도 새로 만들어야 한다.
- 창 구조 golden 만 예외로 두면 모양이 바뀌어도 동작이 같다는 것을 나머지 golden 으로 증명할 수 있다(Q1·Q2).

## 검토한 대안
- ttk 테마만 바꾸기: 의존이 늘지 않는다. 대신 둥근 카드·원형 버튼 같은 참고 그림의 모양을 직접 그려야 해 코드가 커진다.
- 두 방식 비교 시제품 뒤 결정: 사용자 결정(2026-10-13)으로 생략했다.
