# 0002 패키지 구조 (목표 모듈 경계·의존 방향)
상태: 확정      날짜: 2026-10-12 (변경 축별 6모듈 안 승인)

## 조건
- 목적: 백업 대상·저장 방식·자동화를 추가할 때 한 곳만 고친다.
- V1 백업 대상 종류 증가 · V2 저장 위치·방식 증가(이번엔 경계만) · V3 자동화·CLI 증가.
- 고정 축: UI 구성·언어·테마. 번역은 JSON 으로 빼지 않는다.
- Q1 동작 동일 · Q2 자동 테스트만(subprocess 모킹) · C1 pywin32·psutil 선택 · C2 PyInstaller onefile · C3 호환 전부 유지 · C4 한 번에 전체 분리 금지 · C6 `ezBAK.py` 루트 진입점 유지.

## 결정

### 모듈 (모두 `ezbak/` 아래, 지금 도입)
| 모듈 | 무엇이 바뀔 때 수정되는가 |
|---|---|
| `core/` | 백업·복원 절차, 필터·숨김 규칙, 보관 정리 규칙, 작업 로그 문구가 바뀔 때 |
| `targets/` (V1) | 백업 대상 종류가 늘거나 한 종류의 위치·방식이 바뀔 때(브라우저, 드라이버, 앱 목록) |
| `storage/` (V2) | 저장 위치·방식이 늘거나 바뀔 때(로컬·외장·UNC, NAS 연결) |
| `automation/` (V3) | CLI 인자, 스케줄 옵션·config JSON, 예약 작업 등록 방식이 바뀔 때 |
| `winsys/` (I/O) | Windows API·외부 명령 호출 방식, 선택 의존 fallback 이 바뀔 때 |
| `gui/` (고정) | 화면·대화상자·번역 문자열·테마가 바뀔 때 |
- 루트 `ezBAK.py`: 100줄 이하 진입 wrapper 이자 PyInstaller entry. 할 일은 `automation.cli` 로 Headless 요청을 판정·실행하거나, `winsys.elevation` 으로 UAC 를 처리한 뒤 `gui.run(entry_script=os.path.abspath(__file__))` 를 부르는 것뿐이다.
- `ezbak/__init__.py` 는 비워 두고 사용자가 한 번 직접 만든다(0003 §4). `ezbak/CLAUDE.md` 는 두지 않는다. `ezbak/__main__.py`(`python -m ezbak`) 는 도입 조건: V3 원격·일괄 배포에서 pip 설치형 실행이 필요해지면.
- 기존 빈 폴더 `ezbak/core`·`ezbak/gui` 는 그대로 쓰고 `ezbak/utils` 는 지운다(변경 이유가 없는 이름).

### 의존 방향 (지금 도입, 화살표는 import 허용 방향)
```
ezBAK.py → automation, gui, winsys
gui        → automation, targets, storage, core, winsys
automation → targets, storage, core, winsys
targets    → core, winsys
storage    → core, winsys
core       → winsys (fileattrs·paths 만)
winsys     → 표준 라이브러리, pywin32·psutil(선택)
```
- `tkinter`·`customtkinter`(ADR 0004) 는 `gui/` 만 import 한다. `subprocess` 는 `winsys/proc.py` 만 import 한다. 역방향·형제 내부 파일 참조는 금지(각 모듈은 `__init__.py` 의 공개 이름으로만 쓴다). 하위 모듈은 그 패키지 `__init__.py` 의 `__all__` 에 이름이 있을 때만 공개 이름으로 보고 `from ezbak.<모듈> import <하위 모듈>` 을 허용한다(2026-10-13 P5-17 사용자 결정 A — 예: automation.cli·headless·scheduler, targets.apps·drivers, storage.nas. winsys 는 하위 모듈 전부 공개).

### 도메인 타입 (core/model.py, 지금)
- `FilterRule(type, pattern)` — 만들 때 type 을 소문자로 정규화(`'NAME'` → `'name'`), `ext/name/path` 외는 버린다. `FilterSet(include, exclude)`. `DEFAULT_FILTERS` 의 유일한 정의.
- `BackupJob(user, dest, include_hidden, include_system, retention_count, log_retention_days, filters, log_folder)` — `log_folder` 는 C3 때문에 받되 지금처럼 쓰지 않는다.
- `BackupPolicy` — 0001 의 GUI/Headless 동작 차이를 명시 플래그로 담는다(점 파일 숨김, AppData 규칙, 속성 fallback, 여유 공간 확인). `BackupPolicy.GUI`·`BackupPolicy.HEADLESS` 두 상수로 Q1 을 지킨다. P2 에서 행동 플래그 4개(복사 셈 규칙, 북마크 오류 격리, 로그 정리 2회차, 판정 예외 시 포함)를 더하고(같은 원칙으로 P2-4 에서 백업 삭제 오류 격리, P2-7 에서 정리 오류 격리·CRITICAL 결과 반환 추가), 문구·줄 유무·앞뒤 줄바꿈 차이는 `JobLogFormat` 항목에 둔다(2026-10-12 P2 결정 D1, GUI·Headless 절차 함수 2개 안은 채택 안 함). 엔진은 하나로 합치고 현재 차이는 이 플래그로 그대로 보존한다(2026-10-12 결정). 예외는 Headless 작업 로그 줄바꿈 누락 하나만 고친다(0003 §6). 두 동작의 통일 여부는 나중에 따로 정하고 새 ADR 로 기록한다.
- `BackupResult(backup_path, log_path, files, folders, bytes)`.

### 패턴·동시성·캐시
- 엔진은 동기 함수이고 GUI 가 작업 스레드에서 부른다. 콜백은 스레드 안전해야 하며 GUI 어댑터는 큐에만 넣는다.
- 작업 로그 열기·백업 폴더 준비(이름, 같은 이름 폴더 삭제)·사용자 확인은 진입 wrapper(GUI·Headless)가 하고, 엔진 `run_backup` 은 열린 작업 로그·`JobLogFormat`·백업 경로를 인자로 받는다. 두 경로의 준비 순서 차이는 wrapper 에 남는다(2026-10-12 P2 결정 D2).
- 여유 공간은 `winsys/sysinfo.py` `free_space` 를 P2 에서 먼저 만들고 `LocalFolderStore` 가 감싼다. core 는 store 를 거쳐서만 묻는다(2026-10-12 P2 결정 D4).
- 취소(`cancel_event`): 도입 조건 — 취소 버튼 요구가 확정되면(지금 ESC 는 로그만 남긴다).
- 캐시: 도입 안 함(Q4 수치 목표 없음). 조건: 크기 사전 계산과 복사 순회의 속성 조회 중복이 측정상 느려지면, 한 작업 동안만 사는 경로→속성 메모를 엔진이 소유한다.

### 이름 충돌 검토
- 계획서의 `ezbak/logging`, `ezbak/platform` 은 표준 라이브러리 이름이다. 패키지 안 절대 import 에서는 문제가 없지만, 하위 폴더를 `sys.path` 에 넣는 실행(pytest rootdir 삽입, 폴더 안 스크립트 직접 실행, PyInstaller 분석)에서 표준 모듈을 가린다. 쓰지 않는다 → `winsys/`, 로깅 설정은 `core/diag.py`.
- `copy`·`queue`·`types`·`json`·`calendar`·`email` 같은 표준 이름도 파일·폴더 이름으로 쓰지 않는다(`fileops.py`, `bridge.py`).
- `ezbak`(소문자 패키지)와 `ezBAK.py`(루트 모듈)는 Windows 에서 대소문자만 다르다. Python import 는 이름 대소문자를 검사하므로 정상 동작하지만 `PYTHONCASEOK` 설정·도구에 따라 혼동될 수 있다 → 이름은 유지하고(C2·C6), 테스트에 "`import ezbak` 이 패키지 폴더를, `import ezBAK` 이 루트 파일을 가리킨다" 확인을 넣는다.

## 근거
- 경계를 V1·V2·V3 에 그어서 새 브라우저는 `targets/browser.py` 표 한 줄, 새 저장 방식은 `storage/` 파일 하나, 새 CLI 인자는 `automation/cli.py` + `BackupJob` 필드로 끝난다.
- 외부 명령을 `winsys/proc.py` 하나로 모아야 Q2(명령줄만 확인) 테스트가 모킹 한 곳으로 된다.
- UI·언어는 고정이므로 계획서의 `ui/`·`i18n/`·`config/` 를 `gui/` 하나로 합쳤다. `cli/`·`services/schedule` 은 같은 변경 축(V3)이라 `automation/` 으로 합쳤다. 서브패키지 8 → 6.

## 검토한 대안
- **A. 계획서 원안(계층형: cli/core/services/ui/i18n/config/logging/platform)** — 기술문서 다이어그램과 1:1 이라 설명이 쉽다. 대신 새 대상 하나(V1)가 core/browser_backup + services + ui 세 곳을 건드리고, 고정 축(i18n·config)에 경계·안내 파일 비용을 쓰며, `logging`·`platform` 이름 위험이 있다.
- **B. 기능별 수직 분할(backup/, restore/, drivers/, nas/, schedule/ 마다 화면+로직)** — 기능 하나가 폴더 하나라 찾기 쉽다. 대신 폴더마다 tkinter 와 엔진이 섞여 "core 는 tkinter 금지"를 폴더 단위로 검사할 수 없고, Headless 가 GUI 폴더를 import 할 위험이 생긴다. 백업 엔진을 GUI·Headless 가 공유한다는 성공 기준과 맞지 않는다.
- **C. 인터페이스 없이 함수만 이동** — 가장 빠르다. V2 경계가 없어 클라우드·압축 추가 때 엔진 내부를 다시 열어야 한다.

## 결과
- 영향: `ezBAK.py`(wrapper 로 축소), `ezbak/` 6개 모듈, `tests/`, `ezBAK.spec`·`scripts/build_pyinstaller_script.ps1`(entry 그대로, `--add-data icon` 유지).
- 검사: 0003 §3 의 아키텍처 테스트 a(tkinter)·b(의존 방향)·c(subprocess)로 이 ADR 을 강제한다(2026-10-12 승인, P1 부터).
- `resource_path` 는 `winsys/paths.py` 로 옮기되 기준 디렉터리(`_MEIPASS` 또는 현재 작업 디렉터리)를 바꾸지 않는다.
- 예약 작업 인자에 들어갈 스크립트 경로는 모듈 `__file__` 이 아니라 `ezBAK.py` 가 넘긴 `entry_script` 를 쓴다(C3: 비frozen 등록이 패키지 내부 파일을 가리키면 안 된다).
